## Checkbox Group

`Checkbox.Group` manages the state of a set of checkboxes and exposes the checked values.

```tsx
<Checkbox.Group>
  <Checkbox.Root>
    <Checkbox.Control>
      <Checkbox.Indicator />
    </Checkbox.Control>
    <Checkbox.Label />
    <Checkbox.HiddenInput />
  </Checkbox.Root>
</Checkbox.Group>
```

<Example id="group" />

### Controlled

Use `value` and `onValueChange` to control the group. The value is an array of checked values.

<Example id="group-controlled" />

### Root Provider

Create the group store with `useCheckboxGroup` and pass it to `Checkbox.GroupProvider`. This works like `RootProvider`
for a single checkbox.

<Example id="group-provider" />

### Invalid

Set `invalid` on `Checkbox.Group` to mark every checkbox in the group as invalid.

<Example id="group-with-invalid" />

### Max Selected

Set `maxSelectedValues` to cap how many checkboxes can be checked. Once the cap is reached, the rest are disabled.

<Example id="group-with-max-selected" />

### Select All

A parent checkbox can toggle every item in the group. It shows an indeterminate state when some items are checked and is
checked when all are.

<Example id="group-with-select-all" />

### Form

Set `name` on `Checkbox.Group` to submit the checked values with a form. Read them as an array with `FormData.getAll()`.

<Example id="group-with-form" />

### Fieldset

Wrap `Checkbox.Group` in `Fieldset` for a semantic group with a legend, helper text and error text.

## Guides

### asChild Behavior

`Checkbox.Root` renders a `label` element so the control is always labelled. Without it, the HTML and accessibility
structure is invalid.

> When you use `asChild`, make the `label` element the direct child of `Checkbox.Root`.
