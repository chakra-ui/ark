## Anatomy

The menubar owns only a root element. Its items are the triggers of the `Menu` components inside it.

<Anatomy id="menubar" />

```tsx
<Menubar.Root>
  <Menu.Root>
    <Menu.Trigger />
    <Portal>
      <Menu.Positioner>
        <Menu.Content>
          <Menu.Item />
        </Menu.Content>
      </Menu.Positioner>
    </Portal>
  </Menu.Root>
</Menubar.Root>
```

## Examples

### Basic

Each `Menu` inside `Menubar.Root` becomes an item. The menubar handles roving tabindex, arrow keys, `Home`/`End` and
typeahead across the triggers. The menus coordinate opening and closing. No extra prop or wrapper is needed.

While a menu is open, moving to a sibling with the arrow keys or pointer switches to it.

<Example id="basic" />

### Nested Menus

Submenus use `Menu.TriggerItem` as usual. `ArrowRight` on a submenu trigger opens the submenu instead of moving to the
next menu.

<Example id="nested" />

### Vertical

Set `orientation="vertical"` to stack the triggers. Up and down move between them. `ArrowRight` opens the focused menu
as a fly-out.

<Example id="vertical" />

### Disabled

Set `disabled` on `Menubar.Root` to disable every trigger.

Set `disabled` on a `Menu.Trigger` to disable one menu. Keyboard navigation skips it, it is never tabbable, and hover
doesn't open it.

<Example id="disabled" />

### Root Provider

Use the `useMenubar` hook with `Menubar.RootProvider` to read state from outside the component.

<Example id="root-provider" />

## Guides

### Portal the menus

Render menu content in a `Portal`. The menubar treats every `role="menuitem"` inside its root as its own item. An inline
`Menu.Positioner` would have its items picked up as menubar triggers, and keyboard navigation would land on them.

```tsx
<Menu.Root>
  <Menu.Trigger>File</Menu.Trigger>
  {/* ✅ portalled out of the menubar root */}
  <Portal>
    <Menu.Positioner>
      <Menu.Content>{/* ... */}</Menu.Content>
    </Menu.Positioner>
  </Portal>
</Menu.Root>
```

### Skipping the animation between menus

The first open should animate. Moving between menus is a swap, and replaying enter and exit animations there looks like
flicker.

The outgoing and incoming content both get `data-instant` during a swap. Use it to skip the animation while keeping it
for the first open:

```css
[data-menu-content][data-state='open'] {
  animation: fade-in 150ms ease-out;
}

[data-menu-content][data-state='closed'] {
  animation: fade-out 100ms ease-in;
}

/* switching between menus in a menubar */
[data-menu-content][data-instant] {
  animation: none;
}
```

Arrow keys and hovering a sibling trigger set `data-instant`. Closing a menu by clicking its trigger or pressing
`Escape` clears it, so the next open animates.
