Need to access a component's state? You have four options:

| Approach                        | When to use it                                |
| ------------------------------- | --------------------------------------------- |
| The `render` prop               | Read the state of the part you are replacing  |
| `Component.Context`             | Quick inline access via render props          |
| `use*Context` hooks             | Build custom child components that read state |
| `useComponent` + `RootProvider` | Control the component from outside            |

<FrameworkOnly framework="web">

In `@ark-ui/web`, the elements are the API. See [Web Components](#web-components).

</FrameworkOnly>

## The render Prop

When you replace a part with your own element, `render` hands you that part's state alongside its props. No context is
needed for the thing you are already rendering.

```tsx
<Collapsible.Trigger render={(props, state) => <button {...props}>{state.open ? 'Open' : 'Closed'}</button>} />
```

Each part carries the state its machine exposes, so a trigger knows whether it is open, an item whether it is
highlighted, a swatch whether it is checked. See [Composition](/docs/guides/composition) for the shape `render` takes in
each framework.

> **Solid**: the state arrives as an accessor, and the props as a function to call:
> `render={(props, state) => <button {...props()}>{state().open ? 'Open' : 'Closed'}</button>}`

## Context Hooks

Every component exports a `use*Context` hook (like `useDialogContext` or `useMenuContext`). Call it from any child
component to access state and methods without render props.

```tsx
import { Dialog, useDialogContext } from '@ark-ui/react/dialog'

function CustomCloseButton() {
  const dialog = useDialogContext()
  return <button onClick={() => dialog.setOpen(false)}>Close ({dialog.open ? 'open' : 'closed'})</button>
}

export const Demo = () => (
  <Dialog.Root>
    <Dialog.Trigger>Open</Dialog.Trigger>
    <Dialog.Content>
      <CustomCloseButton />
    </Dialog.Content>
  </Dialog.Root>
)
```

The hook returns the same API as `Component.Context`, just without the nesting.

## Web Components

`@ark-ui/web` has no context or hooks. Each root element exposes its state directly.

### Properties

Roots have live properties such as `open`, `value`, `checked`, and `page`, typed on each element. They work like
`input.value`: reading returns the current state, and writing updates it without dispatching a change event.

```ts
const dialog = document.querySelector('ark-dialog')!
dialog.open = true

const select = document.querySelector('ark-select')!
select.value = ['react']
```

Properties are for uncontrolled use. While the controlled attribute (`open`, `value`, `checked`) is present, it wins and
writes are ignored. Values written before the element connects apply once it starts.

### Events

Change callbacks are lowercase events such as `valuechange`, `checkedchange`, and `openchange`. `event.detail` is the
Zag change details object. Events bubble, so filter `event.target` when components are nested.

```ts
const checkbox = document.querySelector('ark-checkbox')!
checkbox.addEventListener('checkedchange', (event) => {
  if (event.target !== checkbox) return
  checkbox.setAttribute('checked', String(event.detail.checked))
})
```

For uncontrolled initial state, use `default-value`, `default-checked`, or `default-open`. For controlled state, set
`value`, `checked`, or `open` and update the attribute from the change event.

### Reading state

Every root and part has a read-only `state`: the root's `getRootState()`, or the part's own, such as an item's
`getItemState()`. It is computed when read and is `undefined` until the element connects.

```ts
select.addEventListener('highlightchange', () => {
  for (const item of select.querySelectorAll('ark-select-item')) {
    console.log(item.getAttribute('value'), item.state) // { value, selected, highlighted, disabled }
  }
})
```

### Methods and the full API

Actions that aren't state, such as `timer.start()` or `clipboard.copy()`, are element methods. They can be called before
the element connects, and they dispatch the same events as the matching user interaction.

The full Zag API is available as `api` once the machine starts. Await `ready` to know when that is:

```ts
await select.ready
select.api!.getItemState({ item })
```

## Computed Controlled Values

To control a prop with a computed value, use a function binding. With `open={a || b}` and `onOpenChange`, the
component's own update wins until the expression changes.

```svelte
<Tooltip.Root bind:open={() => open || dragging, (value) => (open = value)}>
```

</FrameworkOnly>

## Choosing the Right Approach

- **`Component.Context`**: Quick inline access for conditional rendering
- **`use*Context` hooks**: Build reusable child components that need parent state
- **`useComponent` + `RootProvider`**: Trigger actions from outside (like opening a dialog from a menu item)
