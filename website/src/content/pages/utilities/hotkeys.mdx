## Setup

Register a shortcut with `useHotkey`. It listens on the document and cleans up on unmount.

<Example id="basic" component="hotkeys" />

`mod` resolves to Command on macOS and Control elsewhere, so you write the binding once.

## Examples

### Multiple shortcuts

`useHotkeys` takes an array of commands, each with a `hotkey` and an `action`.

<Example id="multiple" component="hotkeys" />

### Sequences

Press one key, then another. `G > H` fires only if both land inside the sequence window.

<Example id="sequence" component="hotkeys" />

### Sequence timeout

`sequenceTimeoutMs` sets that window (default one second). Wait longer and the sequence resets.

<Example id="sequence-timeout" component="hotkeys" />

### Scopes

A command with `scopes: ['editor']` only fires while that scope is active. `store.setScope` swaps an entire set of
shortcuts at once.

<Example id="scopes" component="hotkeys" />

### Form fields

Single keys are ignored while typing in an input, textarea or select. Shortcuts with a modifier, like `Cmd+S`, still
fire. Opt a single key back in with `options: { enableOnFormTags: true }`.

<Example id="form-fields" component="hotkeys" />

### Conflicts

When two commands claim the same shortcut, `conflictBehavior` decides. `warn` is the default and keeps both, `replace`
drops the earlier one, `allow` keeps both silently, `error` refuses the second.

<Example id="conflicts" component="hotkeys" />

### Key state

`usePressedKeys` returns the keys currently held and `useIsKeyPressed` checks one, for cases like Shift extending a
selection.

<Example id="key-state" component="hotkeys" />

### Recording a shortcut

`useHotkeyRecorder` captures whatever the user presses, for a "click to rebind" setting. Escape cancels, Backspace
clears, and chords and sequences both work.

<Example id="recorder" component="hotkeys" />

### Command palette

`useHotkeyRegistrations` returns every registered command with its metadata, so the palette reads from the registry
instead of a second list.

<Example id="command-palette" component="hotkeys" />

Give each command a `label`, `category` and `keywords`, then group, search and call `item.action` on select. Typing
"dark" finds "Toggle theme" through its keywords.

## Guides

### Displaying a shortcut

`useFormatHotkey` returns a formatter bound to the current platform, so `mod+K` renders as `⌘ K` on macOS and `Ctrl K`
elsewhere.

```tsx
const formatHotkey = useFormatHotkey()

return <kbd>{formatHotkey('mod+K')}</kbd>
```

Inside a component, prefer the hook over `formatHotkey` from `@zag-js/hotkeys`, which reads the platform during render
and causes a hydration mismatch. `usePlatform` returns `mac`, `windows` or `linux`.

### Using your own store

Hooks register on a shared default store. Pass your own from `createHotkeyStore` to isolate commands, set defaults or
control scopes.

```tsx
const store = createHotkeyStore({
  activeScopes: ['editor'],
  conflictBehavior: 'replace',
  sequenceTimeoutMs: 800,
})

useHotkeys({ commands, store })
useHotkey({ hotkey: 'mod+S', action: save, store })
```

Create the store outside the component or memoize it, otherwise it is rebuilt on every render. With its own store,
`useHotkeyRegistrations({ store })` returns only that store's commands.

### Enabling and disabling

`enabled` takes a boolean or a function. A function is checked each time the key fires, so it reads current state
without re-registering.

```tsx
useHotkey({ hotkey: 'mod+S', action: save, enabled: () => !isReadOnly })
```

### Reacting to a key release

`options: { eventType: 'keyup' }` fires on release instead of press. Pair it with a `keydown` command on the same key
for push-to-talk.

### Web Components

`@ark-ui/web/hotkeys` exposes the same store through plain functions. Each registration returns a function that removes
it.

| Hook                     | Web                                                     |
| ------------------------ | ------------------------------------------------------- |
| `useHotkey`              | `createHotkey(hotkey, action, options?)`                |
| `useHotkeys`             | `createHotkeys(commands, options?)`                     |
| `usePressedKeys`         | `getHotkeyStore().getCurrentlyPressed()`                |
| `useIsKeyPressed`        | `getHotkeyStore().isPressed(key)`                       |
| `useHotkeyRecorder`      | `createHotkeyRecorder({ onRecord, onCancel, onClear })` |
| `useHotkeyRegistrations` | `getHotkeyStore().getState().commands`                  |
| `useFormatHotkey`        | `formatHotkey(hotkey)`                                  |

```ts
import { createHotkey, createHotkeys, formatHotkey, getHotkeyStore } from '@ark-ui/web/hotkeys'

const off = createHotkey('mod+K', () => (palette.open = true), { label: 'Open palette' })

createHotkeys([
  { hotkey: 'G > H', action: goHome, label: 'Go home' },
  { hotkey: 'escape', action: clear, scopes: ['editor'], options: { enableOnFormTags: true } },
])

const store = getHotkeyStore()
store.setScope('editor')
store.subscribe((state) => state.pressedKeys, render)

button.title = formatHotkey('mod+K')
```

Pass `{ store }` to use your own `createHotkeyStore()`, or `{ root }` to listen inside a shadow root. The recorder
returns an object with `start()` and `subscribe()`.
